# 面板跟随引擎：契约、词汇与边界以上游为唯一真相源

本面板是 `nw`（Nous Warehouse）的辅助驾驶舱，**不拥有任何领域决策**。引擎的 CLI 契约（envelope `schema` / 字段名 / 退出码 / 验收与检查项的冻结 id）、领域词汇、以及「准许面板代跑哪些引擎命令」的边界，一律以上游仓为唯一真相源；上游变更一到，面板跟随——不自创、不背离、不魔改、不在本地复刻引擎逻辑。数据与引擎分家（上游 ADR 0001）之后，这条从「术语纪律」升级为面板的结构性前提。

Status: accepted

## Considered Options

- **面板自建领域模型与自有契约**：排除。双真相源必然打架——上游改一次字段，面板静默错一次，而错的那侧看起来一切正常。
- **只跟大版本、不跟设计演进**：排除。上游的不兼容变更恰恰发生在小步里：数据分家（上游 ADR 0001）、外部源无版本层、扩展多一条 `package.json` 验收（#21）——没有一件等过「大版本」。
- **引擎不可用时面板本地兜底计算**：排除。违背「面板只调用引擎、不复制其逻辑」；缺引擎已有指路屏，兜底等于造第二台引擎。

## Consequences

- **能力探测代替能力假设**：面板按所配引擎的实际子命令 / envelope `schema` 决定入口可用性；缺能力时入口禁用 + 指路，面板**不自行实现替代品**。实例：所配 `nw 0.1.0` 无 `category` / `vps`，故类别输入与 vps 入口一律不给。
- **契约守卫**：不认识的 envelope `schema` → 报「需升级 nw」并给证据，不猜、不降级解析（与 `nw doctor` 对 manifest 的同款做法）；检查项按冻结 id 渲染，措辞不承诺。
- **数据仓根成为核心状态**：数据与引擎分家后，`ls` / `bake` / `validate` / `catalog.json` 都指数据仓；面板以「数据仓根」为一等设置（与 NW_HOME 并列），不假设数据与引擎同仓。
- **词汇有出处**：`CONTEXT.md` 的引擎侧术语必须能在上游文档 / ADR 找到出处；面板侧造词只描述面板自己的机制（驾驶舱、发射仪式、预审、确认闸、代跑……），不得覆盖引擎语义。
- **跟同步是一类工作**：上游每次发版或改设计，跟出一次「契约表 / 域清单 / 准许代跑清单 / 术语表」的差异，单独成票，不混进功能票；差异未清的功能票不开工。
- **边界随之同步**：上游新增写动作时，面板默认仍是「只展示证据与建议命令」；要代跑须先立 ADR（与 ADR-0003 / 0006 一脉）。
