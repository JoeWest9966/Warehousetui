# 响应式双态布局：常畅态 / 紧凑态，改布局不改字号

终端尺寸变化时，面板在两种呈现态间切换：宽度 ≥ 断点（默认 80，即原 `MIN_W`）为**常畅态**——竖左导航、内层栏展开，外观不变；宽度低于断点但不低于最小支持（66×50）为**紧凑态**——左导航折成横向屏 Tab、装配七步与配方五域等内层栏收起、纵向以 `Min` 吸收并提信息密度。铁律：只改排布，永不缩放字号；所支持的最小终端为 66×50，低于 66 宽仍弹守卫屏，但文案改为「调大窗口」、不再建议「减小字体」。

Status: accepted

## Considered Options

- **缩放字号 / 整体缩放**：排除。违背「像玩游戏一样顺手」的稳定观感；等宽字体下缩放会让 CJK 与 ASCII 混排错位（本项目 `unicode-width` 已在乎这个）。
- **单一流式布局（无极值）**：排除。会让大终端失去既有的「驾驶舱」骨架感；双态保住 ≥ 断点的完整外观，只在变窄时换装。

## Consequences

- `MIN_W` 80 → 66，`MIN_H` 保持 24（不回归 24–49 行）；守卫阈值随断点与新下限更新。
- 引入一处纯「尺寸判定」：`size_class(area) -> Comfy | Compact`，渲染与输入共用同一份判定（与 ADR-0005 的布局模型同源）。
- 紧凑态下顶栏 / HUD 一并精简（去副品牌与版本细节、HUD 少给提示、窄时去右侧主题标注），不折行、不引限高；滚轮滚动范围见 ADR-0005。
