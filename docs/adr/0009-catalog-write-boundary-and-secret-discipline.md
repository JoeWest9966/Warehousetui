# 编目册写动作的代跑边界与机密纪律

上游所配 `0.1.0` **本身即带**四组编目命令（`nw vps` / `nw key` / `nw subscription` / `nw tag`，共 14 个子命令，全部落在**数据仓根**下的五本机器写 JSON：`catalog.json` / `vps.json` / `keys.json` / `subscriptions.json` / `tags.json`）。ADR-0007 的 Consequences 写得很清楚：「上游新增写动作时，面板默认仍是只展示证据与建议命令；要代跑须先立 ADR（与 ADR-0003 / 0006 一脉）。」本 ADR 就是那道闸：裁定面板对这四组代跑到什么程度，以及机密本体在面板侧的分界。

Status: accepted

> **决策记录**：跟随同步第 8 轮（spec #50）。差异清单见工单 #51（`notes/51-follow-sync-diff.md`）；本 ADR 是 #53 vps 登记册、#54 标签反查、#56 订阅登记册、#57 key 登记册四张功能票的共同前置。上游依据：`internal/cli/cli.go` 的 `Schema*` 常量与 usage、`internal/{vps,key,subscription,tag}` 四包、上游 `CONTEXT.md` / `README.md` / `docs/tags.md`。

## Considered Options

- **全不代跑（四组一律只给建议命令）**：排除。本工具的存在理由就是「用面板做这些操作、不碰命令行终端」（ADR-0006 同一句话）；编目是数据仓的一等居民，操作者日常要在驾驶舱里登记机器、登记订阅、挂标签，把旗标记忆成本推回给人等于没做。且 `vps` / `key` / `subscription` 的 register 都带引擎自己的 `--yes` 确认闸——上游已经把「拟落账不落盘」的语义焊死了，面板要做的只是把闸结论摊开给人看，与 ADR-0006 的外部源登记同构。
- **一键到底（填完直接 `--yes`）**：排除，同 ADR-0006。没有信息量的确认只是把手滑当天意——编目是信任闸唯一一道。
- **把机密本体收进面板配置**：排除，同 ADR-0006。上游纪律：argv 面无任何明文形参（误粘的 argv 会进 ps / history），本体只从 stdin 进；面板多存一份落盘就是第二真相源。
- **`get` 也代跑、本体铺在屏显上**：排除。见下面「机密本体分界」的裁断——屏显铺一把活钥匙，等于把密钥塞进渲染缓冲，而渲染缓冲会进终端滚动历史、进截图、进快照测试可复现的帧；面板没有任何机制能保证它不扩散。

## Decisions

### 1. 准许代跑的编目子命令（kind 级两张清单）

**准许代跑**：

| 命令组 | 子命令 | 形态 |
|---|---|---|
| `vps` | `ls` | 只读，随 #53 入驾驶舱 |
| `vps` | `register` | **两段式**（预审不带 `--yes` → 摊开五道闸 → 图形确认 → 落账带 `--yes`），同 ADR-0006 |
| `vps` | `rm` | 代跑，但面板加一道图形确认（见下） |
| `key` | `ls` | 只读（投影无本体槽、不印指纹） |
| `key` | `register` | **两段式**，本体经 stdin 喂入（#55 铺的管子） |
| `subscription` | `ls` | 只读（投影无链接槽；到期标记由上游 `status.go` 算好随回音下发） |
| `subscription` | `register` | **两段式**，链接本体经 stdin 喂入 |
| `tag` | `ls` | 只读（反查，本组的主价值） |
| `tag` | `add` | 代跑，**无确认闸**（上游就没有 `--yes`，追加合并、幂等） |
| `tag` | `rm` | 代跑，面板加一道图形确认 |
| `key` / `subscription` | `rm` | 代跑，面板加一道图形确认 |

**一律只给建议命令，不代跑**：

| 命令 | 理由 |
|---|---|
| `key get` / `subscription get` | 上游**唯一回显本体的两个出口**（`data.key` / `data.url` 单槽、不开 `--raw`）。面板不接这个动作：屏显铺一把活钥匙的扩散面（终端滚动历史 / 截图 / 快照帧）面板没有任何机制能兜住。建议命令给到 `nw key get --name <名> \| jq -r .data.key` 这一形态，执行权留给操作者——上游自己也不开 `--raw`、要裸串自己拼管道，上游的裁法本身就是「别让这玩意有个方便的出口」，面板跟着。 |

### 2. 两段式与「无确认闸」怎么写

- **有 `--yes` 的 register（vps / key / subscription）**：预审段 argv **连 `--yes` 的位置都没有**（从构造函数形状上分开，误下发靠类型杜绝，同 `source_register_preaudit` / `source_register_commit`）；摊开引擎的闸结论（`data.gates[]`，id 冻结、措辞不承诺，三态 pass/fail/skip）；**任一不过 = 一个字节都不落**，且面板不放行落账段。落账段与预审段只差 `--yes` 一枚棋，不另改槽位。
**面板加不加闸，看代价是否可逆，不看上游有没有 `--yes`。** 上游没有 `--yes` 只是必要条件、不是判据——下面 `tag add` 与 `rm` 两条不对称，全由这一句推出，第五本册来了不必重新吵。

- **`tag add`**：上游**没有** `--yes`（追加合并没有「覆盖」可确认），且**代价可逆**（幂等、可重放、编目一个字节不变），所以面板**不自己造一道**。幂等由面板复用同一份 argv 保证——同一条命令重跑，编目一个字节不变。悬空引用清理是上游静默做的（上报面只有 `data.cleaned` + stderr 一行），面板必须**显式呈现清了几条**，不假装没发生。闸结论浮层里那一行「无确认闸」要**把判据说给操作者看**（代价可逆故不加），不是只报一个状态。
- **`rm` 五条（vps / key / subscription / tag，上游都没有 `--yes`）**：面板加一道**图形确认**。理由不是「上游没有所以面板补上」，而是**代价不可逆**：`add` 幂等可重放，`rm` 删掉要恢复得重新登记一遍；操作者点错的代价差一个量级。面板这道确认**不改引擎语义**——下发的 argv 与在 shell 里敲的逐字相同，面板只是在自己侧决定「什么时候把它递出去」，这正是「面板只编排」的一部分。删不存在的名：引擎 rc 3 + 结构化证据 + **文件一个字节都不动**，面板原样呈现证据五字段。

### 3. 机密本体在面板侧的分界

上游把 key / subscription 的本体纪律焊死了：argv 面无任何明文形参、只从 stdin 进、`ls` 永不回显也不印指纹、`get` 是唯一回显处且不开 `--raw`。面板自己的铁律是「永不回显密钥、env 只显示 present 布尔、details 可含任意 JSON 但面板不做值猜测」。两者在「取回本体」这一下正面相撞——裁断如下：

**喂入路径（register 两段式）**：

- 本体只经 stdin 进（#55 铺的管子：`run_with_stdin` / `spawn_with_stdin`，喂后即关、即弃）。**面板侧不存在任何明文形参路径**——连「粘贴板里暂存」这类形态都没有；本体要进面板，只有操作者在面板的喂入框里贴一次这一条路。
- 喂入框渲染成**掩码**（不渲染本体字符），日志行只记「已喂入 N 字节」不记内容。
- **在途副本**：两段式要求预审与落账各喂一次（喂入是一次性的、随进程结束即弃，不能复用同一次管道），所以本体在面板侧**必须**在登记流程的在途状态里停留一会儿。裁断：它只以「在途内存 + 一个不打印内容的外包类型」存在——不进渲染缓冲、不进日志行、不进 config、不进任何持久化路径、不进崩溃上报；`Debug` 派生不打印它。「面板侧不留副本」由此拆成两句，各自可判定：
  - **不留引用**：流程结束（落账 / 返航 / 切屏 / 面板退出）随表单一起 drop；`fed_queue` 只是交给 runner 的在途中转，每个事件循环 tick 被 `std::mem::take` 抽空，不是缓存。
  - **流程结束即擦字节**：`SecretBody` 实现 `Drop`，`fill(0)` 擦掉堆里的明文——`Vec<u8>` 的默认 drop 只释放堆、不擦字节，core dump 或内存复用都能还原。喂给子进程的那一份由 runner 在 `write_all` 之后同样 `fill(0)`，链条两端都擦，ADR 这句才不说谎。
  - 明确**不采纳**「让操作者贴两次（预审一次、落账一次）、面板一份不留」：第二次贴错没有对照、当众贴两次机密，且两段式的意义正在于摊开闸结论再决定，中间插一次重贴会把决策打断。
- 「stdin 是终端会一直挂住等人敲」由**引擎侧**拦（上游 `--token-stdin` 的 TTY 闸），面板不绕过、也不复刻一道自己的判定。

**回显路径（get）**：面板**不代跑**，只给建议命令（见上表）。一旦将来要接，前提是先立一篇新 ADR，并同时给出**两句可判定的条件**：① 该出口不经过任何面板可见缓冲（渲染 / 日志 / 快照 / 测试帧）；② 该出口的泄漏面可被证明受控——剪贴板历史可关，或明确声明不可关因而不采纳。第①条是现在这条 shell 方案已经满足的；第②条是剪贴板一类新出口唯一要额外回答的问题。在那之前，面板宁可把人推去 shell。

**投影路径（ls）**：key 的投影**没有 secret 槽、也不印指纹**（面板连「这像是哪把钥匙」都不该让人推断出来）；subscription 的投影**没有 url 槽**。`--scope` / `--rotated-at` / `--expires` 只登记、不设闸——多宽、何时轮换、何时到期归所有者自裁，面板不代管、不提醒、不评审。**到期标记（expiry marking）由上游 `status.go` 读取时算好**，随回音下发 `status` / `daysLeft`，**永不写进文件**；面板只做 `status` → 结果四态 的视觉映射，**本地零日期运算**（全仓无 `Utc` / `chrono` / `NaiveDate`）。7 天阈值是上游的，面板没有阈值可对齐。只标记不治理：不改退出码、不提醒、不靠 ANSI 颜色。

### 4. 与装配的互斥

沿用 ADR-0006：写动作互斥并入既有 `assembling` 语义，登记与装配不同时进行；在途返航时的收敛行为与外部源登记一致（在途返航收不回引擎的写，回音报成功则刷新五域并明示「写可能已落盘」，最终对错交给 PR + 家长审）。

### 5. 边界（四组共有，钉死）

编目条目**绝不进配方 / 锁定集 / bundle / 装配命令**：订阅链接随续费轮换、标签随组织演进，烤进锁定集等于每次换订阅 / 改标签重烤一次派。面板侧对应表述：不提供任何把它烤进去的入口，`nw recipe bake` 的建议命令（#33 / #58）与编目命令零交集。凭据只从进程环境继承（`GH_TOKEN` / `GITHUB_TOKEN`），不存、不写、不回显、不进日志。

## Consequences

- **ADR-0003 的「三类」→ ADR-0006 的「四类」→ 本 ADR 的新口径**：面板代跑的引擎动作现为**六类**——只读三类的 `ls` / `doctor` + `validate` / `source recheck`，写动作三类的 `up` / `source register` / **编目册写动作（vps register+rm / key register+rm / subscription register+rm / tag add+rm）**。ADR-0003 与 ADR-0006 的表述已按新口径修订，`CONTEXT.md` 的「代跑」词条同步，不留第二种说法。
- **订正 ADR-0006 的一处过时表述**：其 Consequences 曾写「`bake` / `recipe new` / `category` / `vps` / 手改配置维持只展示证据与建议命令」。现状：`recipe new` 已由 #58 给出建议命令（维持只展示，未代跑）；`category` **从来就不存在**（`--category` 是 `source register` 的旗标，该能力项已由 #63 移除）；`vps` 由本 ADR 获准两段式代跑。`bake` 与手改配置仍维持只展示证据与建议命令。
- **契约守卫认识性集合扩面**：`KNOWN_SCHEMAS` 从 8 个扩到 22 个（新增 14 个编目 schema）。注意两层分工不被混淆——**认识形状 ≠ 准许代跑**：契约守卫答「我听不听得懂」，能力探测门答「它会不会做」。不认识时仍走「需升级 nw」五字段证据，不 panic、不按旧形状降级解析。
- **编目册骨架三件**（#53 抽出，后三本只写薄适配器）：envelope 投影类型（条目 + 编目路径 + 闸结论，字段恒在不为 null）、按投影字段渲染且遵循确定性排序的列表件、与命令组无关的两段式登记流（预审 → 摊开闸结论 → 图形确认 → 落账 → 刷新）。抽完之后外部源登记**行为逐字节不变**（既有快照全绿）——抽的是复用件，不是改语义。
- **`get` 不代跑**是本 ADR 唯一一处「把操作者推去 shell」的决定，代价是驾驶舱少一个便利出口；换来的是密钥本体一次都不进面板的渲染 / 日志 / 配置 / 快照任何一面。若将来要接，先立新 ADR。
- 退出码不发明新码：四组的码表以引擎为准（0 / 2 / 3 / 4），未登记码走既有 `ExitCode::from_number` 兜底。rc 3 = 闸不过 / 编目坏 / 要删要取的对象不存在；rc 4 = 写 `xxx.json` 失败（**不是用户输入问题**）——面板若把 3 和 4 都渲染成同一句「输入无效」，会把磁盘 / 权限问题误导成「你填错了」。
- 引擎没有某组能力时（所配 0.1.0 四组全有，但老引擎没有），入口禁用并指路，既有门控语义不变；面板绝不自己实现替代品。

## 修订记录（业主裁断，2026-10-12）

本 ADR 的推荐答案第 8 轮由 agent 按 grilling 形态落成文（工单 #52 的说明）。以下五条由业主在一次 grilling 回合里逐条裁定，均为**措辞与代码对齐**或**判据成文**，不改第 8 轮的任何实质决定：

1. **到期标记的算法归属**：原句「到期三态按 UTC 日期在读取时算……7 天阈值与引擎一致」读起来像面板在算，而面板本地零日期运算——`status` / `daysLeft` 由上游 `status.go` 算好随回音下发，面板只做状态映射。已改为明确归属上游（§3 投影路径、§1 表格 `subscription ls` 行）。
2. **`get` 的门**：维持一律只给建议命令；把「将来要接」的前提从一句泛泛的话收紧成两句可判定条件（§3 回显路径）。
3. **在途副本**：「面板侧不留副本」 拆成**不留引用** + **流程结束即擦字节**两句；`SecretBody` 实现 `Drop` 并 `fill(0)`，runner 在 `write_all` 之后同样擦。明确不采纳「让操作者贴两次」（§3 在途副本）。
4. **闸的判据成文**：§2 开头补「面板加不加闸，看代价是否可逆，不看上游有没有 `--yes`」；`tag add` 的闸结论浮层要把判据说给操作者看。
5. **`scopes` 报值**：原只报条数，而第 9 轮的册内过滤按 scope 的值匹配——操作者能按一个看不见的字段过滤。改为原样逐条报，与 `addrs` / `refs` / `logins` 三个槽同口径。
