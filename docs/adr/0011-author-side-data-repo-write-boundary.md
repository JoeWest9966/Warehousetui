# 作者侧工具写数据仓的边界与 datarepo 写侧接缝

spec #95 第一次让面板**自己写文件**：作者侧工具把产出物落在**数据仓根**之下。ADR-0003 / 0006 / 0009 一脉相承的闸是「面板新增写动作默认只展示证据与建议命令，要动手先立 ADR」。本 ADR 就是那道闸——但它裁的不是「代跑哪条引擎命令」（那六类已由 ADR-0009 钉死），而是**面板自有文件写**这条新轴：不经过引擎、零 argv、零 envelope，作者工具在面板侧生长，引擎契约一个字不动。落点即 `datarepo` 写侧接口（与 #101 读侧同层），本篇把它的方法清单当接缝契约一并钉死。

Status: accepted

> **决策记录**：spec #95（作者侧工具，datarepo 接缝·写侧）。落地票：#109 本篇 ADR + 写侧骨架；#110 skill 脚手架（含首套模板）、#111 extension 脚手架（pi-extension 契约）、#112 组件打包器（单文件 + sha256）、#113 配方编辑器（整文件替换写回）四张消费票共用本篇接缝。上游依据：`docs/external-sources.md`（外部源落点与编目纪律）、数据仓现有组件清单样本（`nw-journeys-and-docs.md` 的 component.yaml / lock 形状）、`nw validate` 对 skill / extension / 配方的检查项（脚手架字段校验的事实来源）。

> **修订（工单 #118，accepted）——准许面收窄到一条**：本地包废（#96–#98）后，写侧的两只手随世界一起走：**skill / extension 脚手架（#110 / #111）与组件打包器（#112）整个移除，不加新功能**（父图 out-of-scope 纪律不变）。准许面从 §1 的「三类文件」收窄到**一条**：`recipe.yaml` 的整文件替换写回（#113）。`datarepo::pack` / `datarepo::scaffold` / `screens::scaffold` 三模块删除，「生成 `SKILL.md` 骨架 / `component.yaml` 清单」在代码与文档里零残留；`DataRepo` / `RepoRelPath` / `plan` / `commit` / 确认闸 / 原子落盘 / 互斥（§4 / §5）一字不动，仍是配方编辑器的接缝。作者侧**创作**入口改走既有外部源登记向导（`scan` 预扫 → 引擎 `nw source register`），面板不升级成组件 IDE。§1 的第 2 / 3 类、§3 的两条例子、§4 的三张消费方表随本修订收敛，明细见文末「修订记录」。

## Considered Options

- **面板只生成内容、落盘动作推回给人（建议命令形态）**：排除。本工具的存在理由就是「用面板做这些操作、不碰命令行终端」（ADR-0006 同一句话）；手建目录、手写 yaml、手算 sha256 的错漏正是面板该拦的东西，推回给人等于没做。且脚手架字段的形状校验（对齐上游 validate 检查项）只有面板侧表单能承载。
- **给引擎加写命令（`nw recipe new` 扩展出 scaffold / 组件打包子命令）**：排除，见 Decisions §3：引擎契约冻结，作者侧便利不该占用引擎的契约面，更不该把作者工具的迭代速度焊死在引擎发版周期上。
- **面板经 datarepo 写侧直写数据仓文件**：采纳。配四道纪律：准许面白名单（§1）、禁止面硬边界（§2）、拟落账 + 图形确认 + 原子落盘（§4 / §5）、类型层不可达 NW_HOME（§4）。

## Decisions

### 1. 准许面：数据仓根之下的配方文件

面板写侧只准写**数据仓根之下**的配方文件，且只以**相对路径**指认（类型层保证，见 §4）：

| 类 | 文件 | 消费票 |
|---|---|---|
| 配方文件 | `recipe.yaml`（整文件替换写回） | #113 |

> **工单 #118 前的两类已废**：组件清单（`component.yaml`，#112）与技能脚手架文件（`SKILL.md` 骨架 / extension manifest + 入口文件，#110 / #111）随本地包废从准许面移除——写侧不再有任何**生成**路径，只剩对既有配方文件的**编辑写回**。

产出内容是**面板自有资产**（编辑器状态 + 表单字段），不是引擎逻辑的复刻——上游 bake 消费配方文件但不生产它们，这正是「为什么不给引擎加命令」的事实底稿（§3）。

#### 第四类（窄准许面）：validate 预跑暂存档

`#113` 写回 `recipe.yaml` 前要喂引擎 `validate` 预跑。引擎只读文件、无 stdin，且从配方路径 `filepath.Dir(filepath.Dir(abs))` 自推仓根（上游 `internal/validate`）——要让**跨文件检查**（`catalog.json` / 组件引用）真跑，暂存文件必须落在配方的**同目录**。于是它是「确认前的一次写盘」，本篇为此显式单开这一行，四条约束钉死：

| 约束 | 内容 |
|---|---|
| 隐藏名、确定名 | `.nwt-validate.yaml`：点号开头（不进引用图、不进编目扫描），固定名（上一轮崩溃留下的残档被下一轮 `fs::write` 截断复用，不积垃圾） |
| 不是产出物 | 不进拟落账、不进确认闸、不进 receipt——确认闸摊开的仍只有 `recipe.yaml` 那一条 |
| 跑完即清 | 预跑回音落地（通过 / 未过 / 不可定型）即清 |
| 返航 / 换根也清 | 编辑器任一点返航清；操作者中途换过数据仓根，按**暂存时那个根**清，不把残档留在旧根里 |

「确认前一个字节都不落」的精确口径因此是：**产出物一个字节都不落**。`recipe.yaml` 自始至终未被图形确认不动；暂存档是喂引擎的一次性暂存、不是产出物。§5 的确认闸纪律一字不动。

> **不选「挪出数据仓」**：挪走 scratch 会让引擎自推出另一个仓根，跨文件检查（catalog.json / 组件引用）随之失效——预跑只剩形态面，等于把「写回前必过」这道闸降级。也不选「写进 `recipe.yaml` 再跑」：那等于确认前就落了产出物，比暂存更糟。

### 2. 禁止面：五类东西一个字节都不碰

- **引擎仓**：上游 `JoeWest9966/Nous-Warehouse` 与本面板仓都算——面板不写任何代码仓。
- **NW_HOME**：安装根是目标侧的地盘，写侧不碰。唯一例外是 spec #94 已特批的**日志落盘**（读侧范畴、另一篇已裁的口径，不走写侧接口、不因本篇开任何新口子）。
- **装配产物**：`.nw-manifest`、派目录、`pruned/` 退场区——装配的写只归 `nw up`（ADR-0003 六类之一）。
- **机密编目文件**：`keys.json` / `subscriptions.json` / `tags.json` 仍只走引擎命令（ADR-0009 的写入口纪律一字不动）；`catalog.json`（外部源编目）同样只走 `nw source register` 两段式。编目是信任闸，手写即开后门。这五类名字（外加 `vps.json`）在类型层就构造不出相对路径——`RepoRelPath` 的末段禁名单，写侧连一个越界的值都造不出来。
- **git**：数据仓是 git 托管的，但面板不 commit、不 push、不 init；改动经 PR + 家长审，同编目纪律（「改编目 = 改信任边界，审查规格同改代码」）。

### 3. 为什么不直接给引擎加命令（显式回答）

**引擎契约冻结。** 上游 CLI 面 / envelope / 退出码 / schema 是全仓唯一真相源（跟随引擎，ADR-0007 / 0008）：上游改、面板跟，面板不改上游。给引擎加 scaffold / 打包命令 = 反向修改上游契约，直接违反这条铁律。三条具体理由：

1. **职责错位**：引擎是目标侧装配的唯一执行者，作者侧的配方文件是它的上游产物；把「改一行组件槽 / env 声明」塞进装配引擎，是用作者侧的便利污染目标侧的契约面。
2. **迭代耦合**：模板库（#110 首套、后续团队私模）是面板静态资产，加一个模板不该引擎发一版；作者工具在面板侧生长，速度归面板。
3. **风险面已经管得住**：面板侧写配「拟落账摊开 + 图形确认 + 原子落盘 + 类型层不可达 NW_HOME」（§4 / §5），手滑风险不输给引擎的 `--yes` 闸——没有必要为这一点惊动引擎。

### 4. 写侧接缝契约（方法清单，钉死）

`datarepo::write` 与 #101 读侧同层（`src/datarepo/write.rs`），路径知识仍只有一个家：

- **`DataRepo::new(root: &str)`**：只收**数据仓根**（设置态同一来源，`~` 展开同读侧 `InstallRoot::new`）。类型上没有 NW_HOME 形参——写侧句柄从构造起就不知道安装根的存在。
- **`RepoRelPath::new(raw: &str) -> Result<Self, _>`**：newtype。绝对路径、任一 `..` 段、`/` 或 `\` 混用、空值、NUL——一律构造不出。写侧所有方法只受它；调用方想写「根之外」在类型层就过不去。
- **`DataRepo::plan(writes: Vec<PlannedWrite>) -> Result<WritePlan, WritePlanError>`**：**写前校验**（空拟落账拒、同一次拟落账内重复目标拒、路径防线加深再挡一次）→ 返回**拟落账** `WritePlan`：将写文件清单，每条 = 相对路径 + 内容字节。**一个字节都不落**，形状自持（路径 + 内容 + 清单三样齐），确认闸直接呈现。
- **`DataRepo::commit(plan: &WritePlan) -> Result<WriteReceipt, WriteError>`**：**仅确认闸放行后调用**。逐文件原子落盘：同目录兄弟临时文件（`.name.nwt-tmp`，保证同文件系统 rename）+ rename 覆盖；失败即清临时文件，目标处要么旧内容原样、要么没有，**永不留半文件**。receipt 回报实落路径清单（日志 / 刷新用）。

消费方的形状（工单 #118 后只剩一条）：

| 消费方 | 形状 | 走法 |
|---|---|---|
| #113 配方编辑器 | **整文件替换** | 写回内容走单条 `plan` → 确认 → `commit`（rename 覆盖即原子替换）；写回前的预跑暂存档见 §1 第四类（窄准许面，四条约束） |

> #118 前的另两条走法已废：多文件骨架（#110 / #111）与单文件 + sha256（#112）。`Plan` / `Commit` 由此只面对单文件 plan——多文件逐文件原子的条文（Consequences）保留为接缝的既有能力，不是现行义务。

### 5. 确认闸与互斥（四道共有纪律）

- 所有写动作同一形态：**拟落账摊开（路径 + 内容预览）→ 图形确认 → 才 `commit`**；确认前一个字节不落（同 ADR-0009 两段式纪律，「没有信息量的确认只是把手滑当天意」）。唯一的口子是 §1 第四类的预跑暂存档——它不进确认闸、不是产出物，且跑完即清。
- 与装配互斥：写动作并入既有 `assembling` 语义，登记 / 编辑与装配不同时进行（同 ADR-0009 §4）。
- **写失败的措辞**：落盘失败是磁盘 / 权限问题（引擎 rc 4 同款教训），渲染成「落盘失败」并带上相对路径与人话原因，**不混同「输入无效」**——别把磁盘问题误导成「你填错了」。
- 未设 / 不可用数据仓根时，作者侧入口统一指路（`data_root_cause` 既有三态），不猜、不拿当前目录兜底——写侧连构造都不该发生。

### 6. 面板不碰 git

数据仓的版本归 git，但面板零 git 操作：不 commit、不 push、不 init、不 stash。作者的改动经 PR + 家长审进仓；面板只负责「把确认过的字节写对地方」。

## Consequences

- **这不是「代跑」清单的扩张**：ADR-0003 的六类说的是**引擎命令**；本篇是另一条轴——**面板自有文件写**，零 argv、零 envelope、引擎无感知。`CONTEXT.md` 「代跑」词条一字不动，新增「作者侧工具」词条记这条轴，不留第二种说法。
- **datarepo 从纯读层变读写层**：读侧 `InstallRoot`（NW_HOME）与写侧 `DataRepo`（数据仓根）是两个独立句柄、两类路径知识，同模块并列；「屏幕层零路径拼接」纪律（#101 已有测试先例）自然覆盖写侧——消费票在屏幕层只消费意图级形状。
- **确认闸 / 原子写 / 拟落账只实现一次**：本篇接缝的消费票现只剩 #113（#118 前为 #110 / #111 / #112 / #113 四票），落盘逻辑仍只有一套。
- **多文件 plan 的 commit 是逐文件原子、非跨文件事务**：磁盘中途故障时，排在前面的文件可能已落。缓解 = 拟落账把全清单摊开（操作者确认时就知道会落哪些）+ receipt 实落清单 + git diff 可审计；不做补偿删除（删到一半更危险）。
- **测试基线形态**（随 #109 落地）：fixture 数据仓进去、确定字节出来；写失败场景断言不留半文件；`RepoRelPath` 对绝对路径 / `..` / 分隔符混用的拒构造 = NW_HOME 不可达的类型 + 测试双证。

## 修订记录（工单 #118，2026-10-15）

`#117` 裁定「本地包废」、`#118` 执行面板侧收尾。实质决定只有一句：**移除，不加新功能**（父图 out-of-scope 纪律不变）。以下是本次修订的逐条口径：

1. **准许面收窄**（§1）：从「三类文件」收敛到**一类**——数据仓根之下的配方文件。组件清单（`component.yaml`）与技能脚手架文件（`SKILL.md` 骨架 / extension manifest + 入口文件）两类作废；写侧不再存在任何**生成**路径，只剩对既有配方文件的编辑写回。
2. **消费方收敛**（§4）：三张消费方表收敛到 #113 一张；多文件骨架（#110 / #111）与单文件 + sha256（#112）两条走法作废。方法契约四条（`DataRepo::new` / `RepoRelPath::new` / `plan` / `commit`）与 §5 的确认闸、互斥、失败措辞、根不就绪指路**一字不动**。
3. **§3 的例子换血**：「生成 `SKILL.md` 骨架」→「改一行组件槽 / env 声明」。论据（引擎契约冻结、作者工具不该焊在引擎发版节奏上）本身不变。
4. **创作入口换家**：面板不再承载新建 skill / extension 的表单——那件事走既有外部源登记向导（`scan` 预扫 → 引擎 `nw source register` 两段式，ADR-0006 同一道闸）。面板不升级成组件 IDE。
5. **代码面落点**：`src/datarepo/pack.rs`、`src/datarepo/scaffold.rs`、`src/screens/scaffold.rs` 删除；`datarepo/mod.rs`（模块声明 + 写侧接缝注释 + 「写侧零路径」禁字面量测试）、`screens/mod.rs`（模块声明、转出项、`FormField` 形状——三个实现者全在本次移除面上）、`app.rs`（字段 / 初始化 / 键位 / 弹层守卫 / 打包与脚手架两族方法 / `KeySnap`）、`layout.rs`（两类命中区与 `SCAFFOLD_*` 常量）、`ui/mod.rs`（HUD 打包态提示 + `HELP_ROWS` 三条登记行）、`screens/recipes.rs`（打包浮层整节、脚手架入口行与渲染调用）同步收敛；`DataRepo::root_path` 保留（`datarepo::recipe` 读配方原文仍用它）。
