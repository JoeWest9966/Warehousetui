# 面板跟随引擎:数据仓根、契约守卫、能力探测门——不拿当前目录兜底

驾驶舱与引擎的关系倒挂时,操作者看不出问题出在哪一层。本 ADR 把「跟随引擎」(spec #24)落成三层机制:

1. **数据仓根成为一等设置**(第一刀,#27):与 NW_HOME 并列、持久化进 config;`ls` 显式携带 `--repo <数据仓根>`,**缺根不下发命令**——面板不再以启动时的当前目录兜底。
2. **契约守卫**(#28):不认识的 envelope `schema` → 「需升级 nw」的结构化证据(带收到的 schema 原文与引擎版本),不 panic、不按旧形状降级解析。
3. **能力探测门**(#29):能力清单来自引擎自己对一次无害调用的回答(stderr 人话 / JSON hint),不维护本地能力常量表;缺能力的入口禁用 + 指路。

三种不可用(没设数据仓根 / 目录不可用 / 引擎缺能力)各有各的指路文案,互不冒充。

## Consequences

- 未设数据仓根时五域入口给指路,而不是一张被误读成「没有数据」的空表;设置屏录入后立即刷新,切换无需重启。
- 数据仓根不可用(不存在 / 不可读)不崩溃,给可区分的指路;引擎缺失仍走既有指路屏。
- `commands::ls` 的签名强制携带数据仓根,「不带 `--repo` 让引擎拿当前目录」在类型层面写不出来。
- 配方 / 组件 / 编目的归属一律以数据仓根为准;凭据与仓库可见性不归面板管(上游环境变量纪律,面板零凭据存储)。
- 将来的 `bake` / `validate` 代跑同样显式携带数据仓根;`vps` / `category` 等上游未发版能力由能力探测门自然开启,面板不预做界面。
