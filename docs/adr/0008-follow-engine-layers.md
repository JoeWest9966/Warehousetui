# 跟随引擎三层机制：数据仓根显式化、契约守卫、能力探测门

spec #24 把 ADR-0007 的「跟随引擎」落成三道可执行的闸：**数据仓根**成为一等设置，五域总览命令显式携带，缺根不下发；**契约守卫**只认面板自己认识 `data` 形状的 envelope schema，不认识就给「需升级 nw」证据，绝不按旧形状降级解析；**能力探测门**问引擎「你有什么」，缺的能力入口禁用并指路，面板绝不自己造替代品、也绝不替引擎回答。三道的共同点：判据全部来自当下真实状态——引擎这一跑的回答、或操作者显式设置——没有一道是面板替上游拍板。

Status: accepted

## Considered Options

- **数据仓根缺省时拿当前目录兜底（既有行为）**：排除。正是它让操作者把「空」误读成「没有数据」；上游数据已与引擎分家（上游 ADR 0001），启动目录与数据仓自此毫无关系。
- **数据仓根做成命令行旗标 / 环境变量而非设置项**：排除。面板是交互驾驶舱，持久化设置与 NW_HOME 并列才一致；旗标留给 `--no-mouse` 那类一次性逃逸（ADR-0005）。
- **契约守卫：不认识的 schema 按旧形状尽力解析**：排除。静默摆错数据比报错危险得多——上游改字段时，面板看起来一切正常。
- **契约守卫：不认识的 schema 直接阻断整个界面**：排除。过度。一处契约变更不该让面板瘫痪；给证据，其余部分照常工作。
- **能力探测用本地常量表（记「某版本有没有」）**：排除。上游一发版即失效，等于把「跟随」做成「手工同步」；映射只到「问引擎哪个命令」，答案永远来自当下这一跑。
- **缺能力时面板自己实现替代（本地算漂移、本地列类别）**：排除。违背「只调用引擎、不复制其逻辑」；缺能力已有指路屏，替代品等于造第二台引擎。

## Consequences

- **数据仓根**：配置增 `data_root`，与 `nw_bin` / `nw_home` / `theme` 等并列持久化；None = 未设——面板不猜、不拿当前目录兜底，五域走指路。配置位置随既有约定（XDG），铁律不变：永不存密钥、用户自加的键原样保留。
- **命令构造层**：五域总览命令的签名**强制带数据仓根**——从类型层面杜绝「不带 `--repo`、让引擎拿当前目录兜底」。
- **唯一水闸在引擎调用入口**：缺根时该命令**不下发**，只留一条人话日志；装配 / 健康两类不在此列（它们要的是锁定集路径与 NW_HOME，不是数据仓根）。
- **契约守卫**：面板认识 8 个 envelope schema（`validate` / `up` / `doctor` / `bake` / `recipe-new` / `ls` / `source-register` / `source-recheck` 的 v1）；不认识的合成 `SCHEMA_UNKNOWN` 五字段证据（带收到的 schema 原文与引擎版本），`data` 不解码；未知字段容忍（前向兼容）照旧，绝不 `deny_unknown_fields`。
- **两层分工不可互换**：契约守卫是**面板自己的契约知识**（认不认得出 `data` 形状），能力探测门是**引擎当下有什么**。前者答「我听不听得懂」，后者答「它会不会做」。
- **能力探测门**：探针是一次**无害调用**（不带 `--yes` / `--repo` / `--root` 等会动文件的旗标）；判据读引擎自己的回答——回 envelope = 有，stderr 人话「未知子命令」= 无，解析不出结论 = 探测失败（走既有指路屏语义，不瘫痪、不冒充）。四条探针在所配 `nw 0.1.0` 上实测纯读、不落任何文件。
- **入口清单由面板定义、可用性由引擎决定**：外部源登记 / 外部源复核 / 类别 / vps 四个入口按此顺序呈现；上游 `category` 与 `vps` 在所配 `0.1.0` 上不存在，故这两个入口一律禁用并说明缺的是引擎能力——这是「能力探测代替能力假设」的第一次实证。
- **词汇**：「契约守卫」「能力探测门」随本 ADR 首次定义，并进 `CONTEXT.md`。

## 后续订正（#63，2026-10 跟随同步第 8 轮）

- 入口清单**已不是**上文那四个：指向上游不存在子命令的「类别」已移除（`nw` 没有 `category`，`--category` 是 `source register` 的旗标），并补 key / 订阅 / 标签 三条组级探针。现清单八项：外部源登记 / 外部源复核 / 配方烘焙 / 配方新建 / vps / key / 订阅 / 标签。
- 上文「上游 `category` 与 `vps` 在所配 `0.1.0` 上不存在」只有前半句对：`vps` 在 0.1.0 上就有（探针即判可用），`category` 压根不存在——所以它是**问错了问题**，不是「引擎缺能力」。
- 「入口清单由面板定义、可用性由引擎决定」这条规矩本身不变，并补了两条边界：新增入口必须在 #51 差异表里点名过；探针只能指向上游真实存在的命令面（`get` 永远不进探针清单，它回显本体）。
